# LeoMiniGames v0.6.1 — Theme Runtime & API Expansion

## Theme architecture

- Added `ThemeManager` with live theme switching, isolated external RCC registration, optional SHA-256 verification, atomic install, remove and installed-theme enumeration.
- Added `Constants.qml`: Qt Design Studio-style centralized design token API.
- Built-in Bronze Espresso theme now contains 320 base color tokens and 1,253 semantic/component-state aliases, plus spacing, size, radius, font, icon, control, timing, scale, opacity and game-presentation metrics.
- Added `ThemeSurface.qml` for solid/gradient/texture-backed surfaces. Built-in shell/game rectangles were migrated to theme-aware surfaces.
- Added separate `ThemesPage.qml` and Theme Market client boundary; backend endpoints were not changed.
- Added `theme-sdk/ExampleTheme`.
- `Theme.qml` remains as a backward-compatibility facade.

## Game API

- `GameTheme` exposes runtime color/number/string/surface lookup to modern plugins.
- Added deterministic `GameRandom` with serializable state.
- Added lifecycle-aware `GameClock`.
- Added `GameEvents` local event bus.
- Added optional manifest fields `theme_support` and `theme_surfaces`; they are not trust signals.

## Documentation

- `docs/THEMING.md`
- `docs/PLUGIN_LEVELS.md`
- expanded `docs/PLUGIN_API.md`

## Compatibility

The RCC game package format is unchanged. Legacy plugins do not need to use Constants or GameTheme. Missing theme keys always fall back to the built-in theme. Level 3 trust remains runtime/catalog policy and cannot be granted by a manifest.
