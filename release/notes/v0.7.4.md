# LeoMiniGames v0.7.4

Unreleased development notes. No v0.7.4 package or device qualification is claimed by this file.

## Reliability

- Update checks preserve the newest request when synchronous state observers change channels, clear results or delete the service. Retired checks cannot create duplicate replies.
- Cancelling an update retires its state before abort callbacks run, so a replacement check retains its state and an observer can delete the service safely.
- Input callbacks preserve replacement action values and focus. Stale press/release notifications, reset batches and physical-key mappings cannot overwrite newer input.
- Mod download tickets retain the catalog's package digest and length. Legacy tickets may omit those fields, but cannot redefine them.
- Pending mod/theme ticket requests reject a changed catalog origin. Catalog/download URLs reject embedded credentials.
- Update guidance preserves native, Flatpak and mobile package choices instead of labeling every non-Maintenance installation portable.

## Linux runtime and theme fixes

- Theme duration tokens retain milliseconds; progress geometry no longer collapses into the normalized 0..1 range.
- Online Qt kits include the image-formats module. Desktop bundles require SVG/WebP plugins, and runtime probes decode PNG/JPEG/WebP/SVG through the installed Qt plugins.
- Debian packages explicitly depend on Shapes, Dialogs, QML models, SVG/WebP plugins and fonts. Fedora/Arch packages include image-formats and a baseline font.
- Native packages receive additional tests in fresh runtime containers without Qt development kits. Packaged audio probes exercise effects and music, with a private PulseAudio monitor rejecting silent output.

See [Linux runtime investigation](../../docs/releases/V074_LINUX_RUNTIME.md) for reproduction and validation boundaries.

## Release tooling

- Pending manual QA reports can be prepared from a small source-bound package manifest. Existing reports are preserved; the tool clears stale pass claims and does not invent device evidence.
- QA names follow the canonical version and manifest version mismatches are rejected.
- Publication verifies GitHub package evidence and includes device-test limitations. Manual 25-target QA is optional and strictly checked when supplied.
- Release API responses are read from files to avoid Linux environment-size limits, with regressions for oversized collections and existing public releases.

## Compatibility and validation

The game API remains 0.7. Raw RCC compatibility and existing data boundaries remain in place. The release kit stays at Qt 6.10.2; Qt 6.12 is tested separately on GitHub. HarmonyOS, YLPlugin/YLPkg and pixel-format work remain groundwork, without HAP support, new decoders or a new runtime format.

Prepared runtime changes passed GitHub CI and Qt 6.12 desktop tests at `1c803c9`; local Qt 6.11.1 regression checks also passed. This version bump and main integration require fresh GitHub results and a new exact-source artifact build before a v0.7.4 release. Compilation and automated tests do not establish physical-device behavior.
