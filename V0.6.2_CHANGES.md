# LeoMiniGames v0.6.2 Changes

## Theme architecture

- Expanded the default theme to 300+ base colors, 1,600+ tokens and 5,000+ semantic aliases spanning color, spacing, geometry, typography, motion, scale, opacity, elevation, touch targets, layouts, controls, market UI and game presentation.
- Protected primitive metric units/ratios from external theme overrides so presentation themes cannot change gameplay/application logic constants.
- Kept gameplay rules outside the theme layer through `GameRules`.
- Added transactional external theme replacement/update and corrected fallback asset-root resolution.
- Theme packages remain data-only RCC resources; QML, JavaScript and native libraries are rejected.

## Theme Market

- Added online Theme Market catalog integration with HTTPS-only requests, download tickets, SHA-256 and size verification, package-format checks and minimum-app-version checks.
- Added separate `Explore` and `Installed` Qt models with search, dynamic category filtering and sorting.
- Installed combines built-in, market-installed and local/sideloaded themes.
- Exactly one theme is active at runtime. Applying another theme atomically changes the active id and refreshes theme bindings.
- Active themes cannot be removed from the Installed UI. The built-in fallback theme cannot be removed at all.
- Themes never appear as games in the main game registry/library.
- Added Theme Market access beside Mods/Settings in the Library header while retaining the Settings entry.

## Reusable QML components

Added or standardized reusable token-backed components including themed surfaces, controls, state/focus overlays, loading/empty states, safe-area/layout helpers, game board/tile/HUD/inventory components, virtual action controls, analog joystick, dialogue/list components and Theme Market cards.

## Compatibility

- RCC v1 game/mod package format is unchanged.
- Legacy `Audio`, `Settings` and `Plugins` context APIs remain available.
- Existing v0.6.0 save/settings/plugin APIs remain compatible.
