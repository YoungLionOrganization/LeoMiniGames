# LeoMiniGames licensing files

LeoMiniGames host code is licensed under **GPL-3.0-or-later**.

The canonical GNU GPLv3 text is kept verbatim in `/LICENSE`. The example
`<year>` / `<name of author>` lines at the end of that GNU document are part of
the GPL's own “How to Apply” instructions and are intentionally not edited.

Project-specific application is explicit in `/LICENSE_APPLICATION.md`.

Relevant files:

- `../LICENSE` — canonical GNU GPLv3 text.
- `../LICENSE_APPLICATION.md` — LeoMiniGames program/copyright/license
  application statement and release checklist.
- `../COPYRIGHT` — copyright holder/contributor notice.
- `../NOTICE` — concise distribution notice.
- `LEOMINIGAMES_PLUGIN_EXCEPTION_1.0.txt` — adopted GPLv3 section 7 additional
  permission for qualifying independent packages using designated public
  interfaces.
- `YOUNGLION_MOD_LICENSE_1.0.txt` — proprietary package license for eligible
  packages that explicitly select `LicenseRef-YoungLion-Mod-License-1.0`.
- `../docs/YOUNGLION_DEVELOPER_PUBLISHER_TERMS_1.0.md` — publisher ↔ YoungLion
  distribution-service terms.
- `../docs/OPEN_SOURCE_LICENSE_POLICY.md` — standard OSS license-selection
  policy.
- `../docs/TRADEMARK_POLICY.md` — separate trademark/trust-badge policy.

`LEOMINIGAMES_PLUGIN_EXCEPTION_DRAFT.txt` is retained only as a compatibility
pointer and must not be treated as the adopted terms.
`YOUNGLION_MOD_LICENSE.txt` is retained only as a compatibility pointer to the
versioned canonical file.

Developer verification, Official/Verified publisher status, Native/L3 approval
and package copyright licensing are separate systems. A manifest cannot
self-grant YoungLion trust or Native/L3 capability.

Legacy compatibility remains intentional: older package manifests without the
newer license metadata remain runtime-loadable, while new marketplace
submissions may require stricter metadata.
