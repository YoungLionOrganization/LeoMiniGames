2. DEFINITIONS

“Independent Package” means a game, mod, theme, extension, plugin or other package that:

(a) is independently developed;
(b) does not copy or incorporate GPL-covered LeoMiniGames implementation code except material separately licensed to permit that use;
(c) communicates with LeoMiniGames only through a Public LeoMiniGames Interface and ordinary platform/runtime facilities; and
(d) is not otherwise a Derived Core Work.

“Public LeoMiniGames Interface” means an API, ABI, QML interface, package format, manifest schema, resource contract or SDK surface that the LeoMiniGames project expressly documents and designates for third-party package use.

“Documented API” means a Public LeoMiniGames Interface described in the public LeoMiniGames developer documentation or shipped public SDK, including versioned interfaces deliberately intended for external developers.

“RCC/QML/Data Package” means a separately packaged resource bundle, typically using the documented RCC mount/package contract, whose code and data are loaded by LeoMiniGames through designated public package and QML interfaces.

“Native/L3 Plugin” means a separately built native library or bundle loaded by LeoMiniGames through a specifically designated public Native/L3 ABI. Merely being called “L3”, “native” or “plugin” does not make a component eligible for this Exception.

“Private/Internal Interface” means any LeoMiniGames header, symbol, class, private QML object, build-time implementation detail, undocumented ABI, internal data structure or implementation mechanism not expressly designated as a Public LeoMiniGames Interface.

“Derived Core Work” means a work derived from GPL-covered LeoMiniGames implementation code, including a modified LeoMiniGames core, a fork of the core, or a package that copies, incorporates or adapts protected host implementation beyond separately licensed public interface material.

“Combined Distribution” means distribution in which LeoMiniGames and one or more Independent Packages are conveyed together, through the same archive, installer, repository, store listing, image or release set, while remaining identifiable components under their respective licenses.

3. GENERAL ADDITIONAL PERMISSION

As a special exception, and as an additional permission under GPLv3 section 7, each LeoMiniGames copyright holder granting this Exception permits that copyright holder’s GPL-covered LeoMiniGames material to be loaded, linked, combined and executed with an Independent Package through a Public LeoMiniGames Interface without requiring the Independent Package, solely because of that permitted interaction, to be licensed under the GPL.

Subject to the licenses of all components, LeoMiniGames may be conveyed in a Combined Distribution with an Independent Package without requiring that Independent Package, solely because of the permitted interface interaction, to adopt the GPL.

An eligible Independent Package may therefore use a license selected by its copyright holder, including a compatible free/open-source license or a proprietary license such as the YoungLion Proprietary Mod / Content License.

4. RCC / QML / DATA PACKAGES

An independently developed RCC/QML/Data Package qualifies for this Exception when it:

(a) uses the documented LeoMiniGames RCC/package format and mount contract;
(b) uses only public QML types, public runtime services, documented manifest fields and other Public LeoMiniGames Interfaces;
(c) does not copy protected GPL host implementation code into the Package; and
(d) is not a disguised modification of the LeoMiniGames core.

The fact that LeoMiniGames registers an RCC resource, instantiates QML from it, injects documented services or exchanges documented data with it does not, by itself, require an otherwise qualifying Independent Package to use the GPL under this Exception.

5. MOD SDK TEMPLATES AND EXAMPLES

Code from a LeoMiniGames SDK template or example is covered according to the license expressly attached to that template/example.

The recommended project policy is to license developer-facing templates and minimal examples under a permissive license, normally MIT, so that third-party packages may use them without importing GPL obligations merely by copying template boilerplate.

If a template/example contains GPL-only implementation code, this Exception does not silently relicense that code. Its actual file license controls.

6. THEME SDK

An independently developed Theme Package that uses documented theme schemas, aliases, public QML hooks, asset conventions and package formats qualifies on the same basis as other Independent Packages.

Theme assets and theme code remain governed by the Publisher’s chosen license. This Exception grants no right to YoungLion or third-party trademarks or assets.

7. NATIVE / L3 PLUGINS

A Native/L3 Plugin qualifies only when all of the following are true:

(a) it is separately built and remains a separately identifiable library/bundle or package;
(b) it uses only a Native/L3 ABI expressly designated as public for third-party use;
(c) public ABI headers included by the plugin are separately licensed to permit such inclusion or otherwise lawfully usable;
(d) it does not copy, embed or adapt GPL-covered LeoMiniGames core implementation code into proprietary implementation; and
(e) it does not depend on Private/Internal Interfaces for its essential operation.

Use of private headers, internal symbols, undocumented object layouts, internal C++ classes or implementation-specific hooks is outside the automatic scope of this Exception.

Static incorporation of proprietary Native/L3 implementation directly into the LeoMiniGames core executable is also outside the automatic scope of this Exception unless a separate, express additional permission covers that exact combination.

8. RECOMMENDED PUBLIC NATIVE ABI HEADER LICENSING

For public interface-only headers such as a designated `src/sdk/IGamePlugin.h`, the recommended policy is:

    MIT OR GPL-3.0-or-later

for those interface files, provided the relevant copyright holders have authority to grant both licenses.

The permissive option allows proprietary plugins to include the interface declaration cleanly. The GPL option allows GPL-oriented reuse without ambiguity. This dual license does not, by itself, decide whether the host/plugin combination is permitted; this Plugin / Mod Exception supplies the separate GPL additional permission for qualifying interaction with LeoMiniGames.

Accordingly, for the YoungLion architecture, BOTH measures are recommended:

(1) permissive dual licensing of narrowly scoped public SDK/ABI interface files; and
(2) this GPLv3 section 7 Exception on the LeoMiniGames host material for qualifying Independent Packages.

GPL-covered implementation behind those interfaces remains GPL.

9. NO EXCEPTION FOR PRIVATE OR DERIVED CORE WORKS

This Exception does not permit a recipient to avoid GPL obligations merely by naming code a “plugin”, “mod”, “extension” or “L3 package”.

It does not apply automatically where a package:

(a) copies a Private/Internal Interface in a manner that incorporates protected implementation;
(b) copies or embeds GPL-covered LeoMiniGames host implementation code;
(c) modifies LeoMiniGames core and distributes that modified core as proprietary software;
(d) is substantially derived from the host implementation rather than independently developed against the public interface; or
(e) relies on internal implementation coupling outside the designated interface boundary.

A Derived Core Work remains governed by the GPL to the extent the GPL applies.

10. COMBINED DISTRIBUTION

An Independent Package may be conveyed together with LeoMiniGames in a Combined Distribution, provided that:

(a) the GPL obligations for LeoMiniGames remain satisfied;
(b) the Independent Package’s own license is preserved;
(c) required source, notices and attributions for each component are supplied as applicable; and
(d) the packaging does not falsely state that proprietary code is part of the GPL-covered LeoMiniGames core.

This Exception does not remove obligations imposed by any third-party license.
